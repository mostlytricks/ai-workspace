# Changelog — gravity (the ai-workspace system)

Notable changes to **gravity itself** — the rules in `CLAUDE.md`, the `*.template.*`
stencils, and the `.claude/` commands/scripts. This versions the **methodology**, not
the projects it manages (each project carries its own `CHANGELOG.md`).

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); gravity adheres
to [Semantic Versioning](https://semver.org/spec/v2.0.0.html), read for a *convention system*:

- **major** — a rule projects depend on **breaks**: a renamed/moved convention, a changed
  doc-ownership boundary, a restructure an existing project would now violate. (Example:
  flat `SPEC.<domain>.md` → `.gravity/<domain>/SPEC.md` was a breaking restructure.)
- **minor** — a new template, command, optional doc, or additive rule. Existing projects stay valid.
- **patch** — clarifications, tighter wording, typo/format fixes; no behavioral change to the rules.

The version lives in the **git tag** (`vX.Y.Z`) and the `VERSION` file — never in prose.
A project records the gravity version it was built on via the `> gravity: vX.Y` line in its
root-`CLAUDE.md` router (seeded from `GRAVITY.template.md`), so drift is detectable.

## [3.6.0] - 2026-07-27

### Added
- **`/deploy-kepler` — the third leg of portability: a sibling manager gets updated, not just rebuilt** (`.claude/scripts/deploy_kepler.py` + command; from the user's real workflow — several per-purpose Kepler workspaces on different drives, previously updated by hand copy-paste, which has no version comparison, no deletion tracking, and one slip away from clobbering a local `settings.json`). Manager-side, so no protocol rule changes. The design dissolves both stated worries mechanically rather than by care: the **manifest is `git ls-files`** — the deny-all/whitelist `.gitignore` made executable — so `.claude/settings.json`, `PROJECTS.md`, `repos/` and the tiers are *outside it by construction*, and **Kepler's version is the skeleton commit** (the manager has no SemVer by design; §2 already says manager changes don't bump gravity). A `.kepler-deployed` stamp in the target records the last-shipped hashes, which is what lets the report distinguish a *safe update* (target untouched since last deploy) from a *local modification* (the sibling's owner edited it — kept unless `--force`) and an *orphan* (source stopped shipping it — kept unless `--prune`). Dry-run is the default; it refuses a dirty source (a deploy must be reproducible from a commit) and an overlapping target; on a first deploy every difference honestly reads local-modified because provenance is unknown. Gravity-side sync is deliberately out of scope — `/sync-gravity` runs per project in the target workspace. Proven by fixture drill: first-deploy protection, stamp-based update-vs-modified discrimination, prune-with-local-edit-survival, and both refusal guards. Also fixed while documenting it: the HANDBOOK glossary still said "never `git init` at the root" — the contradiction v3.4.0 purged from MISSION and CLAUDE.md §2 had survived in a third place.

### Changed
- **MISSION template §06 stops restating protocol doctrine** (`MISSION.template.html`; found seeding ephemeris, the first fresh four-doc project in months). Every project's MISSION.html carried a private verbatim copy of the doc-kinds + rates table — which is *protocol* doctrine with one owner (the card on gravity projects, CLAUDE.md's doc map on flat ones), so the template was mass-producing exactly the drift the "one concern, one home" rule exists to kill: N copies that age together and disagree with the owner the day the owner changes. §06 is now two lines — the one-concern-one-home sentence plus a pointer to the owner — with a FILL spot naming which owner applies. Existing MISSIONs aren't migrated (their copies are accurate today; trim on next touch).
- **MISSION template §07 non-goals gained the two tiers the interview already asks for** (`MISSION.template.html` + a matching pointer in `interview.md` theme 1). The Telos theme asks "what would *betray* it?" but the template offered one flat bullet list, blurring permanent identity-guards with merely-deferred scope — a distinction that had to be invented on the fly during the ephemeris interview and which the user then confirmed exactly along that line (orders/multi-user/signals forever-no; news a not-yet). §07 is now **Betrayals (permanent, dated — they're decisions, not vibes)** and **Not-yets (with what would earn them)**, so a future agent can't "helpfully" build a betrayal that looked deferred.
- **`/interview` sanctions batched delivery of the five themes** (`interview.md`). "One theme at a time" read as five round-trips; the real ephemeris run batched four themes into one structured-question call and it was strictly better UX with no loss of theme separation. The rule now: themes stay distinct questions but ship in one call where the tool allows; when the question cap bites, Gate folds into Shape and gets confirmed in the read-back.
- **A betrayal is defined — a load-bearing "no", not a prophecy** (`MISSION.template.html` §07 comment + a derivation block in `interview.md`; from the user pushing back that betrayals are "hard to imagine — a human engineer easily thinks *someday it may be helpful*"). The resistance was diagnosed as correct: "never" reads as a prediction, engineers rightly refuse to predict, and *helpfulness* can't be the test because everything is someday-helpful. The redefinition: a betrayal is a **present-tense fact about the design** — a "no" other decisions lean on, where flipping it means redesign, not extension ("permanent" = "a different project / major version", not a vow). Three mechanical tests replace imagination: the no must *buy* something nameable; adding the feature later must force a rebuild, not a bolt-on; and the **drift test** — a helpful agent would plausibly build it unfenced, because betrayals worth writing arrive disguised as help ("no blockchain" fails; "no auto-rebalancing, one write endpoint away" passes). Cap ~3. The ephemeris interview supplied the proof this works: the user never imagined a betrayal — four candidates were derived by negating the mission sentence's load-bearing words and the user *judged* them (three kept, one demoted to Not-yets) — but the derivation recipe lived only in the interviewing agent's head; now it's written where the next agent will find it.

## [3.4.1] - 2026-07-26

### Changed
- **The observatory explains its own marks — and stops using two glyphs to say "yes"** (`generate_observatory.py`; prompted by the user reading Overview and Queue and finding the signs confusing, which is the standing bar for touching this UI at all). Eight marks competed on one screen doing three unrelated jobs, and **nothing on the page defined any of them**. The diagnosis separated them: *status* (`◑ ✓ ○`) was never the problem — it already renders as colour dot + glyph + word, so it is the clearest thing on the page; *annotation* (`⟡` track, `⚠` attention) was fine but unexplained; and *presence* was the real defect. The SPEC and ARCH columns rendered `⊚` and `☾` — the Orbit 3D metaphor's ring and moon — under headers that **already named the doc**, so both glyphs carried no information beyond "yes" while costing two symbols to memorise. They now render a **check that is a link opening the doc** (absent stays an em dash), which removes two marks and upgrades the cell from *it exists* to *here it is*. The metaphor glyphs stay in Orbit 3D, where they are a visual language with their own legend — the fix was never that they are bad symbols, only that a table is not a star map. A one-line **legend strip** under the tab bar now defines every remaining mark, and the two near-identical checkmarks (`✓` status-stable vs `✔` graduation-proven) collapse to one, so a checkmark means one thing everywhere on the page.
- **Spec Health says what it means — the four numbers are a chain, and now they look like one** (from the user reporting the tab reads great but its *meaning* stays ambiguous, and asking for more on the page because a human engineer is the reader). The tab already carried an explanatory hint, so the gap was never missing text: it explained the **taxonomy** without ever stating the **question**, and its five metrics ran together in one line with nothing saying they are sequential. They are — *is there a SPEC? → do its rules have teeth? → is there a command that proves a change? → does it pass right now?* — so the page now opens with that question in one sentence and renders the rungs as **nested fractions** (rules only count inside fenced domains, passing only inside gated ones), with the **weakest rung flagged** as the place an agent's mistake would actually get through. Ties break to the *lower* rung on purpose, since a gate over toothless rules proves less than the rules do. Each domain card also gained a plain-English **verdict** — "an agent changing `doc` meets 8 machine-checked rules and 5 that rely on a human, and its gate passed just now" — deliberately literal, restating scanned facts rather than grading. Building it caught two encoding bugs in the ladder itself: a rung at `0/5` painted mid-tone despite being as broken as the flagged one (colour now follows the ratio, not just the flag), and a **vacuous** rung — "gates are green" where no gate exists — rendered as an empty alarm-coloured bar, claiming a failure the project had not earned; those are now drawn neutral and excluded from the weakest-link search, the same *unknown-is-not-failure* rule `blocked`-vs-`RED` already follows.
- **One status mark instead of three** (follow-up, from the user reading the new legend and asking why each status appeared *doubled*). Status rendered as a coloured dot **plus** an uncoloured glyph **plus** a word — three encodings of one fact, and pure accretion: the dot was the original indicator and nothing removed it when the glyph and label were added. The glyph can carry both channels, so it is now coloured and the dot is gone. The audit that found this also found the reverse case: on the **Spec Health** and **Graduation** card headers the dot stood *alone*, with no glyph, no word, and no legend entry that matched — a bare colour, which is precisely the encoding a colour-blind reader cannot resolve. Those twelve sites now render the same shape-bearing glyph with a `title` tooltip, so the change removes redundancy in three places and removes a genuine accessibility hole in two. One mark, one meaning, everywhere.

## [3.4.0] - 2026-07-26

### Added
- **`palette.py` — the five-theme family finally has an owner, and a wall that catches drift** (`gravity/lib/palette.py` + `check.py theme`; the debt v3.2.1 recorded rather than fixed: three surfaces draw the same five themes and no file owned them). Merging them was the wrong fix and was rejected: the observatory renderer, the fleet dashboard and the browser-read doc pages each speak a **different token vocabulary** for the same palette (`--surface`/`--ink` · `--panel`/`--text-hi` · plain dict keys), because they are different surfaces, not duplicates — deduplicating would have re-emitted CSS for every themed page with no screenshot test to catch a regression. What was actually missing was ownership, so `palette.py` declares only the **anchor hues** all three must agree on (`bg` · `ink` · `dim`, plus the CSS-only `h1-grad`) together with the vocabulary map a checker needs to compare tokens that were never meant to match. `THEME_DRIFT` is a **FAIL**, unlike `ARCH_PATH_DEAD`'s WARN, because a drifted palette *ships*: it renders wrong on every page that surface generates and is invisible in review, since each file stays internally consistent. Under-claims by design — star gradients, ring/moon hues, chart axes and per-status glyph colours stay owned locally, as nothing cross-checks them. All 20 anchors agreed on the day it landed, so it starts green; proven by tamper (one `--ink` shifted a single digit → FAIL, restored → OK).
- **`bootstrap.py` — the manager half of portability: a workspace can now be reconstructed** (`.claude/scripts/bootstrap.py`). The protocol half shipped in v3.2.1 (the lib travels, so a clone renders and checks itself); the gap left was that the *manager* couldn't be rebuilt at all. Tracking only the skeleton is the correct boundary (§2 — no umbrella repo), but it means a fresh clone has the rules and the instruments and no `repos/`, no tier folders, no index, no junctions. Bootstrap creates the folders, seeds `PROJECTS.md` from the sample when absent, and re-links every `repos/` project into the tier **its index row names**, repairing dangling links on the way — one code path for junctions (Windows) and relative symlinks (POSIX), driven through `link_project.py` so no shell can corrupt a path. It is equally the fix for a broken link on an established machine, and safe to re-run. Three deliberate refusals keep it honest: it **never guesses a tier** (an unindexed `repos/` folder is reported under *"NOT filed"*, never filed somewhere plausible — a guessed row makes the whole index untrustworthy), it **never clones** (remotes would require a manifest naming private repos, which has to be a deliberate export), and it **never edits an existing `PROJECTS.md`**. Proven on a fixture across all three states: bare clone, an indexed project missing its junction beside an unindexed one, and a genuinely dangling junction (removed, re-made, content reachable through it).

### Changed
- **The architecture map/trace split moved from stencil to practice — `knowledge-viewer` is the worked example.** v3.3.0 shipped the two templates and `ARCH_PATH_DEAD`, but the anchor is opt-in, so across the whole fleet **zero pages carried a single `data-path`** and the wall verified nothing anywhere. The system page's *Components & Boundaries* table is now the **Domain × Layer grid** (rows = the `.gravity/` capability domains, columns = the layers a request crosses, `security`/`logging`/`ops` as bands, `integration` left to §04 since it owns the arrows), and `search/ARCHITECTURE.html` is the matching **trace** — its four ASCII flows became lane-guttered traces whose lane names are the map's own columns, so the two pages share one coordinate system. 54 anchors now resolve, verified by tamper (a moved path → `ARCH_PATH_DEAD`, restored → OK). Drawing the grid immediately produced a finding the prose had only implied: `server/src/sections.ts` appeared in four rows, and the *"a file in three rows is a layer, not a capability"* rule promoted `SectionRegistry` to its own column — the two-axis doctrine arriving mechanically rather than by assertion. Two cells were corrected against the source while anchoring them (`web.ts` is the single-origin proxy that *removes* CORS rather than configuring it; `chat/audit.ts` is the deliberate content-capturing exception to the content-free logging invariant) — the kind of quiet inaccuracy an unanchored diagram keeps forever.
- **The fleet is current: all 14 adopted projects synced v3.2 → v3.3** (12 `.gravity/` projects re-carded and re-libbed, `pulsar` and `astra` stamp-only as flat two-doc projects), and `PROJECTS.md`'s adoption table reconciled — including two rows that had never been added (`aihub-demo`, `temp-analysis`, both flagged by `ADOPTION_MISSING_ROW`). `check.py workspace` now reports tiers, index and adoption table all agreeing. The sweep also caught a live hazard in the mechanical layer: `knowledge-viewer`'s `CONTEXT.md` *mentions* `<!-- gravity:router -->` in prose, and a fence rewrite that matches an opening marker without requiring its closing partner would have overwritten the file — fence detection now demands a real open/close pair.
- **`MISSION.html` reconciled with what the workspace actually does.** §03 and §06 both still forbade `git init` at the root while the root *is* a git repo with a remote — a contradiction `CLAUDE.md` §2 had already resolved and the mission doc had not, leaving the two most-read docs disagreeing on the workspace's most load-bearing rule. Both now state the real boundary (the root versions the *shell*: deny `*`, whitelist the skeleton, every tier folder denied). §05 gained the Kepler/gravity split it predated entirely — the protocol distribution, the travelling lib, and `.gravity/<domain>/` were absent from the doc-system table. The horizon block was re-cut to match reality: the walls wedge is marked shipped, portability is the *now*, and rather than invent a third horizon the later shape is an honest `OPEN:` — inventing one would violate §06's own SDLC admission test.

## [3.3.0] - 2026-07-26

### Changed
- **The card is the canon — the workspace manual stops restating the protocol.** The Kepler/gravity split (v3.0.0) gave the protocol its own home, but the workspace `CLAUDE.md` §6 kept carrying the full project-side doctrine it had already exported — SPEC anatomy, graduation, the chore/comet rule, the `.gravity/` layout, the navigation discipline all lived twice, and every protocol change had to be written twice (the exact drift `one concern, one home` exists to prevent). The manual's §6 now collapses to the manager-side essentials (the two mandatory files + session ritual, the four-doc pipeline, the ownership table) plus one block naming `gravity/GRAVITY-PROTOCOL.md` as **the** canonical project-side statement — 5,507 → ~3,590 words. Cut-and-carry, not just cut: the two §6 concerns the card lacked (**walkthroughs** and the **intake door**) migrated into the card's doc-kinds table first, so nothing lost its home. The split now cuts both ways by rule: workspace rules are never embedded in the card; protocol rules live only in the card.
- **Templates cite the card, never the workspace manual.** Eleven stencils carried `see workspace CLAUDE.md §6`-style citations — unreachable from a cloned project (the exact portability failure the card fixes) and, post-collapse, pointing at doctrine that moved. Every protocol-doctrine citation in `gravity/templates/` now names `.gravity/GRAVITY.md`, which travels with the repo; the one deliberate exception is `CONTEXT.template.md`'s tier-shaped Next-Step note, which is genuinely manager-side. `CLAUDE.template.md` also slimmed (789 → ~560 words): its 11-line doc list — a drifting copy of the ownership table — drops to the doc-pipeline lines plus a delete-me note telling `.gravity/` projects the fenced router block already owns the map, and the legacy `Document Authoring` section (superseded by the fenced block since v3) is gone. The same prune swept `docs/HANDBOOK.md` (7,061 → ~4,770 words): the slash-command table returns to one-liners (`.claude/commands/<name>.md` is the one home for procedure — the `/observatory` row alone had grown to ~400 words), and glossary entries for card-owned doctrine (work layers, chores, domains, SPEC anatomy) compress to definition + pointer; the brownfield chapter and the manual workflows stay whole, since they are the delegated-to owners, not copies.

### Added
- **Proof freshness — `run_gate.py --all` sweeps every fenced domain and records the outcome**, surfaced as a per-domain chip in the observatory's Spec Health tab (no new tab, no new doc kind). This closes the one gap in gravity's proving story: SPEC enforcement tags say which rules have *walls*, the Behavioral Contract says which behaviours have a *named test*, and `GATE_DEAD` proves the named script *exists* — but all of that proves a test is named, never that it passes. A walkthrough captures green output at ship time and then freezes. So a domain could show walls, a gate, and a fully graduated contract while its gate had been red for a month, with no page in the system knowing. Results land in the self-ignoring `.gravity/observatory/gates.json` (`scan_gate_runs` reads it; generated, never authored — "does it pass right now" changes at test-run rate, faster than the fastest doc rate, so a typed version would lie between commits).
- **`ARCHITECTURE.domain.template.html` — the domain-level stencil that never existed.** There was exactly one architecture template and it was a *system* template; every per-domain page was invented from scratch, so seven pages carried seven outlines and a reader re-learned the page at each domain. The two levels now split by **question**, not by scope: the system page is the **map** ("where does anything live, what crosses what?") and a domain page is the **trace** ("how does this one capability work, top to bottom?") — one row of the map expanded down the layers, with a lane gutter reusing the map's own layer names so the two pages share one coordinate system. A **flow, not a graph**: a flow is an ordered path that fits a screen, whereas a domain-scale graph is N² edges and becomes a hairball; a graph earns its place only where N is tiny, which is `integration`'s Boundary Map. The centrepiece was already being hand-drawn — knowledge-viewer's `search/ARCHITECTURE.html` carries four ASCII `<pre>` flows — so this stencils what projects already do rather than inventing ceremony.
- **`ARCHITECTURE.template.html` reshaped around a Domain × Layer grid.** The old §03 *Components & Boundaries* table is retired into it, and §04 now *references* `integration/SPEC.md` instead of restating the contract. The grid renders the two-axis doctrine literally: vertical (capability) domains are rows, layers are columns — on a multi-runtime project those columns *are* its structural domains — and cross-cutting domains (`security`, `logging`, `ops`) are **bands** across the whole grid rather than rows. `integration` is neither, since it owns the arrows. **An empty cell is a decision, not a blank**: cell states carry their reason (`—` absent by decision · `◑` modeled/blocked · `?` unsourced · `shared` two domains couple here), so "auth persists no tokens until encryption is approved" becomes visible instead of derivable by grepping for a file that isn't there. It **renders the registry and never becomes one** — the row set must match the `.gravity/` folders, which remain the sole owner of domain existence. One rule fell out of drawing it: a file may appear in two rows (that's where capabilities couple, and naming it beats hiding it), but **a file in three rows is a layer, not a capability** — promote it to a column. The vertical/horizontal test, made mechanical.
- **`ARCH_PATH_DEAD` (WARN) — the wall that keeps an authored diagram honest.** Grid cells and trace nodes carry `data-path="<file>"`; `check.py arch` (also `check_project.py --only arch`) asserts each still exists. WARN, not FAIL: a dead Gate breaks the change loop, a dead diagram path only misleads a reader, and putting every doc page on the critical path of every refactor is how a checker earns reflexive ignoring. Under-claiming three ways — the anchor is **opt-in** (an unconverted page is silent, never nagged), unresolvable values are **skipped rather than guessed** (globs, unfilled stencil markers, prose), and a `:123` line suffix is dropped so line drift never fires it. It catches a **moved or deleted file only** and says so: it cannot tell you an arrow reversed or a branch was added and never drawn, so the templates stamp `authored · last reviewed <date>` and the CLI reports *"no resolvable anchors — nothing verifiable"* rather than a bare OK on a page whose anchors are all stencils.
- **Authored and generated pages now declare which they are.** The observatory and the architecture pages share a visual language on purpose — one is cheaper to read than two — but have opposite provenance: the observatory is generated, git-ignored and disposable; an architecture page is authored, committed and human-maintained. A page that *reads* as auto-derived is a page nobody maintains, so provenance is stamped rather than implied.
- **The recorded state is four-valued, never two: `blocked` is not `red`.** A gate that could not start — missing tool, absent fixture, or a server it can't reach — proved nothing either way, and reporting that as a failure would be worse than reporting nothing (the `LIB_STALE` under-claiming rule: unknown is not stale). The very first sweep justified it: knowledge-viewer's `search:eval` exits 1 with `ECONNREFUSED` when the dev server is down, which is emphatically not "search regressed". `stale` is likewise claimed only when both timestamps are known — a run is flagged `predates HEAD` when the proof is older than the code it claims to prove, and no git means no staleness judgement at all. Every chip carries the captured output tail on hover, so a misclassification is always auditable rather than authoritative.

- **Orbit 3D's HUD toggles respond to the mouse again** (couplings / tracks / trails, top-left). The HUD sits inside `#view`, whose `pointerdown` handler unconditionally called `setPointerCapture` to drive camera drag; capture retargets the following `pointerup` to `#view`, so the `click` resolved on `#view` and the checkbox never toggled — only the keyboard (space), which bypasses pointer capture, worked. `pointerdown` now returns early for events inside `#hud`, letting the controls own their own clicks.

Scoped deliberately to the canvas: the panel, the dashboard and every `MISSION.html` / `ARCHITECTURE.html` keep their bright readable paper, because that palette is one shared family under a single `dash-theme` key.

## [3.2.1] - 2026-07-26

### Fixed
- **Orbit 3D obeys Kepler's third law — orbital period is now set by distance alone** (`generate_cosmos.prepare`). Speed used to encode a composite "activity" index (`3×PLANs + doc mass`, ×1.6 when ◑, ×recency), which was wrong twice over. It was **redundant**: every input already owned a dedicated channel — mass → planet size, PLANs → satellites, status → radius + colour, recency → comet trail — so motion, the one channel that costs seconds of watching to read, carried nothing new. And it **inverted**: the eye reads *tangential* speed (`r/period`), not angular period, so in knowledge-viewer the ○ planned `security` (activity 19.7, outermost) visibly crossed the canvas faster than the ◑ `agent-console` that is 3.5× hotter, and orbits crossed (`dictionary` at r=486 lapped `search` at r=444) — P² ∝ a³ broken in a workspace named *Kepler*. Now `period = 22s × (r/150)^1.5`: status sets the distance, the distance alone sets the speed, so the active inner band genuinely runs fastest and screen speed falls monotonically outward (kv: 22s → 145s across 10 domains, close to the old 27–208s feel). The activity index is unchanged and still **printed as a number** in each domain's card, where it is actually legible. Legend now reads "inner orbits faster (Kepler)".

### Added
- **The lib travels with the project — a gravity repo now renders and checks *itself*, off-workspace** (`gravity/lib/` + `.claude/scripts/install_lib.py`; the pain, found by asking where `/observatory` output lands: the protocol card made a cloned repo self-*describing*, but every instrument that reads `.gravity/` lived in the workspace, so a clone carried all the facts and no way to see them — precisely the machine that matters, the GitHub-less workplace, was the one that couldn't render). `install_lib.py <project>` copies the whole lib into `<project>/.gravity/lib/` with its own `VERSION` stamp, and `/adopt-gravity` + `/sync-gravity` now do it as part of the mechanical layer (same verbatim contract as the card: re-copy to upgrade, **never hand-edit an installed module**). Installed, the instruments need **no arguments at all** — the lib's own location names its project: `python .gravity/lib/generate_observatory.py`, `python .gravity/lib/check_project.py`, `python .gravity/lib/run_gate.py <domain>`. Proven on a bare copy of knowledge-viewer's docs with no workspace anywhere above it: 10 domains, 5 seams, drift card live, stdlib only. New `check_project` findings **`LIB_MISSING`** / **`LIB_STALE`** mirror `PROTOCOL_MISSING`/`PROTOCOL_STALE`, with the same under-claiming rule — `LIB_STALE` is judged only when a *newer* distribution does the judging, because a bare clone genuinely cannot know a newer version exists.
- **`project_arg.py` — the portable "which project, and where does output go"** (`resolve_target` / `observatory_dir` / `installed_root`). Path-first by rule: a token that is a real directory is used as-is, and the workspace's alias resolver is reached only when present, so the protocol never requires the manager. `run_gate.py` and `scan_project.py` moved onto it too (both had their own workspace-path assumptions; `run_gate` previously *required* `resolve_project.py` and simply broke off-workspace).

### Changed
- **The observatory renders into the project it describes** — output moved from `.claude/dashboard/observatory/<name>.html` to **`<project>/.gravity/observatory/index.html`**, with a sibling `.gitignore` of `*` so the folder ignores itself. The page is visible to anyone who opens the repo, and stays *generated*: a committed page is one that can go stale in git, which the page's own footer forbids ("a wrong page means doc drift"). The command splits the work into two layers on purpose — **mechanical, applied** (re-copy the protocol card verbatim from the template, bump the `> gravity: vX.Y` router stamp to `VERSION`, verify via `check.py consistency`, reconcile the adoption-table row) and **judgment, reported** (every `CHANGELOG.md` section between the old stamp and now is read, and convention changes the project might violate come back as a quoted checklist — a sync never restructures a project as a side effect). Built so a weaker agent can't invent a version: every version is read from `VERSION`, a stamp line, or a changelog heading. Human procedure: HANDBOOK "Upgrade a project to a newer gravity". The `PROJECTS.md` **Gravity adoption** table gains a **`card`** column (and drops its hardcoded "v1.0" wording), the HTML dashboard renders a live `card vX.Y` / `no-card` chip per `.gravity/` project, and `/triage` spot-checks the table against disk.

### Added
- **`check.py spec` — the spec-honesty checker** (first slice of the *conformance* half named in v1.2.0): verifies every `.gravity/<domain>/SPEC.md` against the repo's reality so enforcement tags can't silently rot after `/new-spec` made them honest at authoring. FAILs on provable lies — `SPEC_UNFILLED` (template leftovers like `<FILL` / `[test:name]`), `GATE_DEAD` (the Gate names an npm script or path that no longer exists; scripts resolved through root + workspace `package.json`s), `TAG_DEAD` (a `[test:<name>]` matching no script and no test-ish file) — and WARNs on weak signals (`GATE_MISSING`, `TAG_UNBACKED`, `RULES_UNTAGGED`); non-npm projects skip all npm-based checks (under-claim, never fabricate). HTML comments are stripped before scanning — the enforcement legend legitimately spells the tag grammar (`[test:name]`) inside a comment (caught by the `/new-spec` golden-scenario replay below and fixed; the initially-reported "live catch" in `knowledge-viewer`'s integration SPEC was this false positive).
- **`/interview <project>`** — structured elicitation, the content-seeding twin of the structural commands: `/init-project` seeds stencils and `/new-spec` extracts truth from code, but a new or stuck project's *why/walls/shape/gate/next* exists only in the user's head. Gap-scans first (never asks what the docs already answer), asks five themes **strawman-first** (a guess to correct beats a blank question; corrections carry more signal), follows up only on contradictions, routes each answer to its one owner-doc (§6), and writes unresolved items as visible **`OPEN:`** lines — the `/new-spec` honesty rule pointed at a human: never fabricate intent. Ambition-gated (small tools get two docs, no MISSION/PLAN ceremony); ends with a read-back confirmation; never commits. Two modes, one core: **seed** (blank/partial docs) and **re-interview** (only the OPEN items of a stuck project).
- **Feature-scoped interview + growing-project PLAN conventions** — for projects that grow by accreting features rather than marching an arc. **`/interview <project> <feature>`** is the intake ritual: runs `/new-domain`'s *is-it-a-domain* gate (default verdict: *slice* — anti-sprawl), elicits the **use scenario** as `given/when/then`, then writes either a wired new domain or a `PLAN.<slug>.md` slice plus its spine/queue row. **`templates/PLAN.template.md`** (new, the 11th stencil) is the per-domain/per-slice "what/next" doc — Goal · **Scenario** (`given/when/then`) · Slice · Verification · `OPEN:` questions · Next — now also what `/new-domain` seeds its starter PLAN from. **`IMPLEMENTATION_PLAN.template.md` gains a SLICE-QUEUE VARIANT** (one template, two shapes, like the SPEC integration variant): rolling `now / next / later` lanes with exactly one slice in `now`, replacing fake phases on accretive projects. The maturation pipeline is now explicit end-to-end (CLAUDE.md §6 + SPEC template): a scenario enters as PLAN intent and is **promoted to the SPEC Behavioral Contract only once a named test asserts it** — intent graduates to contract by earning a wall, never by rewording.
- **Golden scenario for `/new-spec`** (`.claude/scenarios/new-spec/`) — guards against the *fabricated wall*: a SPEC whose Gate names a script that doesn't exist, whose `[test:<name>]` points at no test, or which ships template leftovers. ## [1.2.0] - 2026-07-02

### Added
- **Golden-scenario harness for gravity's own commands** (`.claude/scenarios/`) — gravity now tests the commands that *claim* to wire things up. A scenario is a triple: `(command, golden-input fixture, deterministic structural assertions)`. The agent step (running the command) stays manual; the assertion is a script. First scenario: **`/new-domain`** — copies a clean one-domain fixture, the agent adds a second domain, and the checker proves it's wired into all four registry indexes with nothing orphaned (catches the half-wired/orphaned-domain bug).
- **`check.py` — structural-invariant checker** (`.claude/scenarios/check.py`) — `check_gravity_consistency(project_dir)` reads the four registry owners (Doc Map, router table, MISSION "system in N domains" row, `IMPLEMENTATION_PLAN.md` status spine) and reports `UNDERWIRED` domains and `ORPHAN_ROUTE` rows via heuristic slug-match. CLI: `consistency` (one project), `scenario` (assert a golden-scenario's postconditions), `selftest` (proves the checker against a good + deliberately-broken fixture).

- **Project aliases — `resolve_project.py`** (`.claude/scripts/`) — a short token resolves to a canonical project with **no central registry** (PROJECTS.md stays the workspace index, not an alias table). The alias is a per-project identity fact, so a project **declares its own** via a `> alias: <slug>` line in its root `CLAUDE.md` (seeded from `CLAUDE.template.md`, next to the `> gravity:` stamp) — authoritative and owned per project. Resolution order: exact name → **declared alias** → unique acronym as a convenience (`amos` = architecture-memory-os, short ≤2-char tail segments like `os` kept whole) → unique substring (`compass`), refusing to guess when ambiguous. So a project gets a free derived alias immediately and can *claim* an intentional one. `check.py --project <alias>` resolves them; other project-taking commands can adopt the same helper. First declared alias: **`amos`** (architecture-memory-os).
